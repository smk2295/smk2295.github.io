**Ling, C., Zhao, X., Zhang, X., Cheng, W., Liu, Y., Sun, Y., Oishi, M., Osaki, T., Matsuda, K., Ji, J., Bai, G., Zhao, L., & Chen, H. (2024). [Uncertainty Quantification for In-Context Learning of Large Language Models](https://arxiv.org/abs/2402.10189). NAACL 2024 (main conference).**

## Why Standard UQ Tools Don't Fit ICL

Standard uncertainty-quantification tools for LLMs — predictive entropy, ensembling, MC-dropout-style methods — were designed around two sources of randomness: the model's parameters and randomness in generation. In-context learning introduces a third source none of those tools were built to isolate: **the prompt itself is a choice**. Which demonstrations are picked, how many, and in what order can shift predictions on a fixed underlying task — a property of the prompt construction, not of the model or of label noise.

## The Decomposition

The paper splits an ICL prediction's *total predictive uncertainty* into two named components:

- **Aleatoric uncertainty** — attributed to randomness in which demonstrations were selected. Estimated by resampling many different demonstration sets (and/or orderings) for the same task and measuring how much the predictive distribution varies across them.
- **Epistemic ("configuration") uncertainty** — the residual uncertainty that remains even after accounting for demonstration selection, attributed to the model's own limitations.

Formally, this follows the same law-of-total-variance decomposition Kendall and Gal use for vision uncertainty:

$$
\text{Var}[\text{total}] = \underbrace{\text{Var}[\text{demonstration-set choice}]}_{\text{aleatoric}} + \underbrace{\mathbb{E}[\text{residual variance} \mid \text{fixed demo set}]}_{\text{epistemic}}
$$

## Estimating It Without Retraining

ICL has no gradient step to get posterior samples from, so the estimator works by **resampling and re-inference**:

1. Draw many demonstration sets from the available pool of labeled examples for a task.
2. Run the model on each resulting prompt.
3. Use the spread of the resulting output distributions as the aleatoric term.
4. Use the within-prompt predictive entropy (or similar) as the epistemic term.

## Evaluation

Tested across multiple LLMs and classification/QA-style ICL benchmarks, against baselines that don't separate the two sources (e.g., plain predictive entropy on a single fixed prompt):

- The decomposed estimate correlates better with actual prediction correctness/calibration than the undecomposed baselines.
- The aleatoric component specifically tracks how much accuracy varies when the demonstration set is swapped for a fixed model and task — confirming that a meaningful share of ICL's apparent uncertainty is attributable to prompt construction, not the model.

## Where This Sits Relative to Function-Vector Approaches

The estimator's inputs are entirely the model's *outputs* under many resampled prompts — it never inspects internal activations.

| | This paper | Internal-representation approaches |
|---|---|---|
| Model access needed | Black-box (outputs only) | White-box (activations) |
| Cost per query | Many forward passes | Can be closer to one pass |
| What it measures | How much the output moves under input perturbation | The model's internal task representation directly |

## Takeaways

1. A meaningful share of what looks like ICL "uncertainty" is really sensitivity to which demonstrations happened to be picked — not a property of the model alone.
2. Being model-agnostic is a real advantage, but it comes at the cost of needing many forward passes and only ever seeing uncertainty indirectly, through output perturbation rather than internal representation.
3. This is the closest prior baseline for uncertainty in ICL, and the natural question it leaves open is whether the same decomposition can be estimated more directly and cheaply from the model's internals — which is where function vectors come back in.
